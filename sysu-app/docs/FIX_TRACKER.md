Shared mobile-rule checkpoint (2026-10-08): canonical `frontend/firestore.rules` now requires explicit active approved roles and driver-only owned mutations, supports bounded split-name pending registration/basic completion, and matches the sysu-go mirror. The latest combined demo suite passed 58/58, including 10 existing web rule regressions; these are not 58 new web tests. Deployed rules/migration and remaining mobile location/POD/profile contracts are still unverified. See [mobile tracker](../../sysu-go/docs/FIX_TRACKER.md) and [mobile evidence](../../sysu-go/docs/RELEASE_FIXES_TDD.md). Do not deploy strict shared rules alone as proof that every legacy mobile write works.

Mark a finding DONE only when its complete "done when" condition is met and the fix commit or configuration version, test scenario or command, environment, expected and actual results, and redacted evidence link are recorded. Regression tests must demonstrate that they catch the original failure and pass after the fix. Deployment findings also require the specified staging or deployed configuration evidence; local tests alone are insufficient.

Use synthetic data, isolated Firebase emulators or staging, and fake SAP fixtures for these historical scenarios. Do not reproduce destructive failures in production. Some proposed test scripts in the plan did not exist at this checkpoint; test IDs below describe planned acceptance scenarios, not executable commands or passing results.

P0 findings must close before public release. P1 findings must close or have a tested technical constraint that removes the risk; verbal acceptance is insufficient. Deferred P2/P3 findings require an ACCEPTED RISK record with an owner, rationale, deadline, and release-owner decision; they must not be marked DONE. Closing tracker entries alone does not authorize release without the test plan's required evidence.
