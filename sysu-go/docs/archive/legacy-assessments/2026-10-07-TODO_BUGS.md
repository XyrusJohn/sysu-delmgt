# SYSU Go bug and improvement backlog

> Historical assessment dated 2026-10-07. The items below record findings and proposals at that date; unchecked boxes do not describe current implementation status. See the [companion assessment](2026-10-07-SYSU_GO_ASSESSMENT.md) and current [fix tracker](../../FIX_TRACKER.md) before acting.

## Critical findings recorded on 2026-10-07

- [ ] **BUG-1: `PERMISSION_DENIED` for the Firestore `truck_companies` collection.** Logcat reported `E/TruckCompanyRepo: PERMISSION_DENIED: Missing or insufficient permissions. Cached 0 truck companies`. Proposed fix: permit authenticated drivers to read the collection through Firestore rules, or fetch it from the backend API. Affected area: Firestore rules and `SecurityGuardRepository.kt`. Original estimate: about 10 minutes.
- [ ] **BUG-2: The `scanToken()` Firestore fallback always returned `queuePosition = 1`.** When the Railway backend was sleeping, a driver could see position 1 even when others were ahead. Proposed fix: query the queue after the fallback write and calculate the actual position. File: `app/src/main/java/com/sysu/go/network/QRApiService.kt`. Original estimate: about 30 minutes.
- [ ] **BUG-3: `registerTrip()` had no fallback.** The historical report described silent failure when Railway was offline, whereas QR scanning had a Firestore fallback. Proposed fix: direct Firestore write or exponential-backoff retry. File: `app/src/main/java/com/sysu/go/network/TripApiService.kt`. Original estimate: 1–2 hours.
- [ ] **BUG-4: Inconsistent `driverId` in `sap_assignments`.** Some historical paths used a Firebase UID and others a queue document ID, so `DriverShipmentSync` could miss assignments and the App Fleet Manager could show the driver as unassigned. Proposed investigation: confirm that `sapAssignmentController.js` consistently writes the Firebase UID. Files: App backend `sapAssignmentController.js` and Go `AssignmentActivity.kt`. Original estimate: 30 minutes plus any fix.

## High-priority findings recorded before wider release

- [ ] **BUG-5: `clearSession()` did not clear trip data.** Logging out mid-trip and signing into a different account could leave stale trip state. Proposed fix: call `clearTripSession()` from `clearSession()` in `SessionManager.kt`. Original estimate: 5 minutes.
- [ ] **BUG-6: Duplicate Firestore instances in `QueueDetailsActivity`.** Both `db` and `firestoreDb` were created with `FirebaseFirestore.getInstance()`. Proposed fix: remove `firestoreDb` and use `db` consistently. Original estimate: 10 minutes.
- [ ] **BUG-7: GPS pin emoji could render incorrectly in a POD image overlay.** The literal emoji was reported as an encoding risk on some devices. Proposed fix: use Unicode escape `\uD83D\uDCCD` in `ImageStorageHelper.kt`. Original estimate: 5 minutes.
- [ ] **BUG-8: Release build did not enable obfuscation.** The assessment reported `isMinifyEnabled = false`, a larger APK, and visible class names. Proposed fix: enable minification/resource shrinking and review ProGuard rules in `app/build.gradle.kts`. Original estimate: 30 minutes plus tuning.
- [ ] **BUG-9: Android emitted `pod_updated`, but the App dashboard had no listener.** The web POD view needed a manual refresh. Proposed fix: add a `dashboard.js` listener that refreshes the affected shipment row. Original estimate: 30 minutes.
- [ ] **BUG-10: Firebase ID tokens were not refreshed before API calls.** The assessment anticipated 401 responses when a one-hour token expired. Proposed fix: call `user.getIdToken(true)` or check token expiry before requests in `TripApiService.kt` and `QRApiService.kt`. Original estimate: about one hour.

## Technical debt recorded at the time

- [ ] Core network components (`QRApiService`, `TripApiService`, `SessionManager`, `DriverStatus`, and `DriverShipmentSync`) lacked unit tests. Proposed JUnit and MockK/Mockito coverage. Original estimate: 1–2 days.
- [ ] No Espresso UI test covered the QR-scan-to-queue journey. Original estimate: 2–3 days.
- [ ] Activity-owned state lacked ViewModel/StateFlow. Rotation could lose state and trigger extra Firestore reads. Proposed ViewModel and StateFlow/LiveData per screen. Original estimate: about a week.
- [ ] The Kotlin `SocketManager` singleton was difficult to mock. Proposed injectable class or interface wrapper. Original estimate: about a day.
- [ ] `QueueDetailsActivity`, `MainActivity`, and `GeneralTrackingActivity` mixed UI, Firestore, socket, permission, and business logic. Proposed repository/use-case separation. Original estimate: 1–2 weeks.
